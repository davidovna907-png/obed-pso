# Правила работы с репозиторием «Обед ПСО»

## Язык

- Весь текст — интерфейс приложения, комментарии в коде, сообщения коммитов и ответы — на русском языке.

## Обновление меню по фото

1. Если пользователь присылает фото — это меню кафе **на завтра** для приложения «Обед ПСО». Исключение: фото из поездки (виды, люди, достопримечательности) или с пометкой «в альбом» — это фотоальбом «Калининград», см. раздел «Фотоальбом «Калининград»» ниже.
2. Распознай с фото все блюда (и цены, если они указаны) и **полностью замени** ими текущее меню в `index.html`.
3. **Меняй только JSON внутри блока `<script type="application/json" id="menu-data">`** в `index.html`. Всё остальное в файле (HTML, CSS, JS, дизайн, отправку заказов, срок приёма заказов до **21:00**) не трогай и не создавай приложение заново.
4. Сразу закоммить и запушь изменения в ветку `main`, без уточняющих вопросов.
5. Если что-то на фото не читается — не выдумывай: поставь у этой позиции пометку «уточнить» и в ответе напиши, что именно не удалось прочитать.
6. В ответ коротко напиши «Меню обновлено» и список блюд (с ценами, если они есть).

## Формат JSON в `menu-data`

- `date` — дата меню с фото в формате `ГГГГ-ММ-ДД`.
- `collectBy` — всегда `"21:00"`, не менять.
- `cafe`, `phone`, `deadline`, `note` — оставлять как есть, если на фото не указано другое.
- `sections` — массив разделов `{ "title", "portion", "items": [...] }`; для раздела «Премиум» добавить `"premium": true`.
- Блюдо: `{ "id", "name", "price", "desc"? , "grill"? , "new"? }`
  - `id` — короткий уникальный код по разделу: супы `s1…`, горячее `h1…`, премиум `p1…`, салаты `c1…`, завтрак `z1…`, напитки `d1…`, выпечка `b1…` (латиница + цифра, иначе не работает импорт заказов из чата).
  - `price` — только число.
  - `desc` — состав или уточнение (например, `"2 шт"`).
  - `"grill": true` — если на фото у блюда значок гриля/углей.
- Нечитаемое название — в `name` пишем то, что видно, и добавляем «(уточнить)». Нечитаемая цена — `"price": 0` и в `desc` добавляем «цена: уточнить».
- После правки проверить, что JSON валиден.
- Если меню на ту же дату публикуется повторно (исправление, «уточнить»), сохранять `id` уже существующих блюд: новым блюдам давать следующий свободный номер, `id` убранных блюд не занимать. Иначе уже сделанные заказы молча поменяют блюда.

## Публикация

- Приложение для коллег: https://davidovna907-png.github.io/obed-pso/ — GitHub Pages из ветки `main`, обновляется через 1–2 минуты после пуша.
- Тема приложения — всегда тёмная, независимо от настроек телефона: `data-theme="dark"` на `<html>`, тёмный цвет `#141918` в `theme-color` и в `manifest.webmanifest`. Не менять. Картинка для кафе остаётся светлой.
- `sw.js` — фоновая часть для уведомлений о новом меню (ничего не кэширует). При обновлении меню не трогать.
- Для установки на экран телефона нужны `manifest.webmanifest`, папка `icons/`, теги в `<head>` и скрипт в конце `index.html`: он подхватывает новое меню или новую версию приложения, когда приложение открывают снова. При обновлении меню их не трогать.

## Общий заказ

- Заказы всех коллег хранятся в Google Таблице владельца через Apps Script: код — `apps-script/Code.gs`, адрес веб-приложения — константа `ORDERS_API` в начале скрипта `index.html`. Пустая константа — заказы хранятся только на телефоне.
- При обновлении меню `ORDERS_API` не трогать.
- Коллега видит только свой заказ: вкладки «Меню» и «Мой заказ». Все заказы, общую сумму, файл для кафе и вкладку «Коллеги» видит только организатор — после ввода кода организатора (он на листе «Настройки» таблицы владельца). Код в репозиторий не записывать.
- Файл для кафе (картинка, текстовый файл, «Скопировать») — только блюда, количество, суммы и итог, без фамилий.
- Срок приёма — `collectBy` (21:00) накануне даты меню: после него коллега не может менять заказ (только организатор). Кнопки «Очистить весь заказ» при общей таблице нет: заказы на каждую дату хранятся отдельно и нужны для архива.
- Архив (вкладка «Архив», только организатору): заказы по дням за последние 120 дней с листа «Заказы», суммы по коллегам за месяц, копирование заказа дня для кафе.
- Уведомления о новом меню (Web Push): телефоны подписываются в «Мой заказ» / над меню, подписки — на листе «Уведомления». Рассылка запускается сама, когда приложение с новым меню впервые обращается к таблице; скрипт сверяет дату с меню на сайте и шлёт один раз на дату. После обновления меню через 2–3 минуты (когда GitHub Pages обновится) можно разослать сразу: `curl -sS -L -H 'Content-Type: text/plain;charset=UTF-8' -d '{"action":"notify"}' "<ORDERS_API>"` — ответ `sent` показывает, на сколько телефонов ушло.
- Сводка организатору: каждый вечер около 21:00 (расписание ставит `setup()`, функция `eveningSummary`) скрипт считает заказы на завтра и шлёт «Обед ПСО: сбор закрыт — N человек, сумма» только на телефоны с пометкой «Организатор» на листе «Уведомления» (телефон помечается, когда подписка отправлена с кодом организатора). В выходные (меню на завтра нет и заказов нет) — молчит. Кнопка «Прислать сводку сейчас» — в «Заказы» у организатора.
- Папка `deutsch/` — отдельное личное приложение «Deutsch jeden Tag» (курс немецкого, https://davidovna907-png.github.io/obed-pso/deutsch/) со своими `manifest.webmanifest`, `sw.js` и иконками. К «Обеду ПСО» не относится: при обновлении меню не трогать.
- Если меняется `apps-script/Code.gs`, владельцу нужно заново опубликовать его в Apps Script: заменить весь код (копировать удобно со страницы https://davidovna907-png.github.io/obed-pso/setup.html), «Сохранить», вверху выбрать функцию `setup` → «Выполнить» → разрешить доступ (если просит), затем «Начать развертывание» → «Управление развертываниями» → ✎ → «Новая версия» → «Начать развертывание» (адрес не меняется). Проверки сервера (шифрование, подпись, запросы) — в истории этой работы; криптографию в Code.gs без проверки на эталонах не менять.

## Фотоальбом «Калининград»

- Папка `kaliningrad/` — путеводитель по поездке 11–17.10.2026 (приезд 10.10) (свой `sw.js`, он же даёт альбому работу без интернета), `kaliningrad/album/` — фотоальбом этой поездки: https://davidovna907-png.github.io/obed-pso/kaliningrad/album/ (фильм с музыкой, которая генерируется в браузере: у каждого дня своя мелодия — `dayMusic` в album-data, сейчас приезд — «Вечер на острове Канта» (`ballad`, тихая баллада: гитарный перебор и фортепиано, во втором проходе струнный квартет — виолончель и скрипки с вибрато; сочинена «в духе «Yesterday»», которую пользователь просил для приезда), 1 день — «Аллеи Амалиенау» (`amal`, в духе «Experience» Эйнауди: фортепиано перебирает аккорды восьмыми, проходы нарастают — одно фортепиано, мелодия с виолончелью, струнные), 2 день — «Берег Кранца» (`kranz`, в духе «Shallow»: куплет — гитара перебором и «голос» без слов, перед припевом дробь на томах, в припеве удар по струнам, барабаны и бас, во втором проходе струнные), 3 день — «Янтарное лето» (`leto`, в духе летнего хита «Хочу на море» YAKIMANKI: укулеле, маримба, хлопки, волны каждые четыре такта, во втором проходе свист); прежние «Балтийский вальс» (`waltz`), «Ветер с Балтики» (`breeze`) и «Балтийский прибой» (`surf`) остались в «Музыке» на выбор; 4 день — «Хорал Кафедрального собора» (`organ`, органная: педаль, выдержанные аккорды, хорал, во втором проходе пассажи; у органных тембров звук не затухает, эхо больше — `wet` у мелодии), 5 день — марш из Шестой симфонии Чайковского (`march`, это не сочинённая мелодия, а запись `music/tchaikovsky-6-3.mp3`: отрывок 3 мин из записи Musopen, общественное достояние CC0 — у таких мелодий в `TUNES` поля `file` и `credit`, ноты не играются, только такты для смены кадров; брать только записи CC0/PD с надёжным источником, указывать их в `credit`, громкость выравнивать ~ −23 дБ, как у сочинённых; записи под авторским правом (например, «Experience» Эйнауди, которую пользователь просил для 1 дня) на сайт не класть — вместо них сочинить свою мелодию в том же настроении (не копируя мелодию и гармонию), взять запись CC0/PD или предложить «Свою мелодию для одного дня» в «Музыке»: пользователь выбирает свой файл, он хранится только на его телефоне (IndexedDB `own-days`) и звучит в фильме этого дня); 6 день — «Небо над Лавой» (`lava`, в духе поп-рока Burito «К небу протянуты руки», которую пользователь просил скачать: гитара с перегрузом — глушёные восьмые в куплете, открытые в припеве, бас, барабаны, дробь на томах перед припевом, во втором проходе синтезатор); 7 день — «Прогулка» из «Картинок с выставки» Мусоргского (`promenade`, запись `music/mussorgsky-promenade.mp3`: Musopen, Skidmore College Orchestra, CC0, 1:41 — играет по кругу, в конце мягкое затухание и пауза 0,8 с); новым дням пользователь может попросить новую мелодию — тогда сочинить её в `TUNES` и прописать в `dayMusic`; открытки с оборотом, карта, «Янтарная шкатулка»). К «Обеду ПСО» не относятся: при обновлении меню не трогать.
- Фото «в альбом»: `python3 kaliningrad/album/tools/photo.py --day N [--place ID] [--town KEY] [--title "…"] [--memory "…"] --write файлы…`. Скрипт уменьшает фото, убирает EXIF и геометки, кладёт их в `kaliningrad/album/photos/` (превью в `photos/t/`) и дописывает в JSON `album-data` в `kaliningrad/album/index.html`. Видео (.mov/.mp4) он же переводит в MP4 H.264 до 1280 px (HDR с iPhone — в обычный цвет), без метаданных, с обложкой; в альбоме видео играет в открытке и в фильме. `--mute` — видео без звука (пользователь просит убирать голоса, чтобы звучала музыка). `--turn 90|-90|180` — довернуть видео, если телефон записал его боком (проверять кадры). Видео с морем — со своим звуком прибоя: в album-data `"sea": true` (в фильме музыка на это время сильно тише — константа `DUCK` в коде альбома, по просьбе пользователя «значительно убавить»); если в них слышны голоса, места с голосами заменять шумом моря из того же видео (голоса видно на спектрограмме `ffmpeg … showspectrumpic`). Остальные видео — без звука (`--mute`), в том числе все видео 1 дня, кроме моря в Светлогорске. Если пользователь просит оставить в видео его звук (например, звон рынды, 4 день), а голосов нет — звук оставить и в album-data поставить `"sound": true` (как `sea`: в фильме своё звучание, музыка тише). После того как видео получило `sea`/`sound` или его файл переделан, запустить `python3 kaliningrad/album/tools/clips.py` — он кладёт рядом звук `photos/<id>.mp3`: на iPhone видео в фильме играет только без звука (кадры меняются без нажатия пальцем), поэтому прибой и рында звучат из этого файла через движок музыки. Видео в фильме загружаются заранее по очереди, ближайшее первым (`preVideo`, на 5 кадров вперёд); новые видео держать не тяжелее ~2,5 Мбит/с (`ffmpeg … -crf 23 -maxrate 2.2M -bufsize 4.4M -movflags +faststart`), иначе на мобильном интернете не успевают. Если файл видео переделан, к его `src` добавлять `?v=2` (3, …), иначе телефон покажет старую копию из памяти. Остальной код альбома при этом не трогать.
- День берётся из слов пользователя или из даты съёмки. `place` — id места из путеводителя (`PLACES` в `kaliningrad/index.html`); ставить, только если место узнаётся уверенно, иначе `town` или ничего.
- `memory` (история на обороте открытки и в фильме) — только словами пользователя, ничего не придумывать. `cast` — имена спутников для титров, только если пользователь их назвал (сейчас `["Мамуля"]`).
- На фото обычно двое: пользователь (жёлтая куртка, зелёная кепка) и мама (белая куртка, белая кепка). Пользователь просил подписывать их: «С мамулей …», «Мамуля …», «Я …». Остальных людей по именам не подписывать.
- Коллаж из нескольких фото (пользователь просил «3 фото на одной странице, интересным форматом»): `kaliningrad/album/tools/collage.py` (полароиды под разными углами на тёмном фоне, подписи от руки; как получить шрифты — в начале скрипта), затем `photo.py` и в album-data `"collage": true`. Исходные фото коллажа отдельно не добавлять. Еду и напитки — страницей-меню: `collage.py --menu` (подпись «Название|пояснение»). Похожие повторяющиеся кадры пользователь просит собирать «сверху — посередине — снизу»: `collage.py --column` (высокая страница; её файл сохранять шириной 1200 px, превью 800 px — `photo.py` ужал бы её до 2000 px по высоте; в открытке она листается вверх-вниз). Пользователю нравится «по 3 фото на странице»; порядок на странице — люди (мы с мамулей) сверху и снизу, достопримечательность или вид в центре. Пересобранной странице — тот же `id`, к `src` и `thumb` добавить `?v=2` (3, …); исходники уже собранных страниц — в истории git (до коммита 6ab1f0a).
- Если маршрут дня отличался от программы — `dayRoutes` (`{"2": ["kgd","gur","sha","zel","kgd"]}`), новые города — `extraTowns` (`{"gur": ["Гурьевск", 20.603, 54.770]}`).
- Справка «Знаете ли вы?» обычно одна на день (в середине фильма дня и вверху главы). Если пользователь просит справку о месте у конкретной страницы — `factAt` в album-data (`{"d7-02": "tretyak", "d7-10": "zoo"}`, id кадра → id места с `fact`): тогда в этот день справки стоят перед своими кадрами и в фильме, и в главе, а общей справки нет.
- Места, которых нет в путеводителе, — в `extraPlaces` (`{"sinag": {"name", "old", "year", "town", "day", "fact"}}`), дальше `--place sinag`. Факт — только проверенный.
- Дни вне программы путеводителя — в `extraDays` (уже есть день 0 «Приезд», 10.10: `--day 0`). Описание дня словами пользователя — в `note` дня из `extraDays` или в `dayNotes` (`{"1": "…"}`), показывается в главе и в фильме.
- Если день прошёл не по путеводителю (например, свободный день 13.10 стал экскурсией в Балтийск), заголовок главы — в `dayInfo` (`{"3": {"title": "Самый западный город России", "kind": "Экскурсия в Балтийск"}}`), маршрут — в `dayRoutes` (день в одном городе — `{"4": ["kgd"]}`).
- `dayScenes` — рисунок главы дня: `city`, `cats`, `sea`, `dunes`, `amber`, `bridge`, `kirche`, `plane`. Например `{"3":"dunes"}`, если в свободный день были на Куршской косе.
- Фильм смотрится по дням: на обложке выбор «Все дни / Приезд / День 1 / …» (только дни с фото), кнопка «Смотреть фильм · день N»; фильм дня начинается с его главы, в конце — «Смотреть следующий день». По умолчанию выбраны «Все дни» (альбом готов, им делятся; 17.10), выбор пользователя держится до конца дня. Выбор дня есть и в полоске дат над главами, и кнопкой вверху каждой главы.
- Финал всего альбома — `finale` в album-data (`{"id": "d6-08", "text": "ПРОДОЛЖЕНИЕ СЛЕДУЕТ…", "sub": "СПАСИБО, КЕНИГСБЕРГ — КАЛИНИНГРАД 💓☀️🫂"}`): это видео пользователя (прогулка по набережной, снято 16.10) идёт последним в общем фильме и в фильме последнего дня поездки (7 день, просьба пользователя: «продолжение следует» — в заключительный день), за ним — кадр с надписью словами пользователя, потом титры. В фильме своего дня (6) это видео идёт обычным кадром, без надписи. На финальном видео и надписи (`fin: true` у кадров) музыка не переключается на мелодию дня этого видео, а доигрывает мелодию последнего дня. Новые фото последующих дней не ставить после финала: если пользователь пришлёт другое завершающее видео — поменять `id`.
- Фильм дня — не длиннее 3 минут (просьба пользователя). Кадры отбирались галочками (17.10 пользователь сказал, что альбом готов, и кнопку «Отобрать для фильма» убрали из главы и кнопку «Отобрать кадры для фильма» с обложки; код отбора оставлен, вернуть кнопки — по комментариям в `renderAlbum` и `renderPick`): в главе кнопка «Отобрать для фильма», отмеченные кадры остаются в альбоме, но не идут в фильм (на телефоне пользователя — сразу). Кнопка «Отправить список» копирует текст «…убрать из фильма… id: d1-05 d1-12…» — получив его, ставить этим кадрам в album-data `"film": false` (удалять файлы совсем — только если пользователь прямо попросит «удалить»).
- Пользователь присылает фото каждый день поездки, альбом установлен у него на экран «Домой» (кнопка «Установить альбом на телефон» на обложке, подсказка для iPhone). Приложение при открытии само подхватывает новые фото, поэтому после добавления достаточно запушить. С 17.10 альбом готов и им делятся: на обложке нет служебных строк («Сегодня день N… присылайте фото», «Новое в альбоме»), на кадрах нет пометок «новое», на обороте открытки без истории нет подсказки про чат, в «Музыке и показе» нет блока «Как пополнять альбом» — пользователь просил «чистое приложение, без доп. информации»; такие подсказки не возвращать.
- Альбом публичный, как и весь сайт: фото увидит любой, у кого есть ссылка. Номера чужих машин размывать. Билеты (пользователь просит класть их на страницу рядом с фото места) — не скриншотом, а перерисованной карточкой: логотип с билета, событие, дата и время, место; без ФИО, телефона, почты, номеров заказов, штрихкодов и сумм. Скрин карты с местом пользователя — только если он сам хочет его показать (16.10 — «показать, что я далеко от Калининграда», `d6-14`); строку телефона сверху (время, связь, заряд) обрезать.
- После правки проверить, что JSON валиден, закоммитить и запушить в `main`.
